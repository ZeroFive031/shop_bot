# Бот-магазин с оплатой в Telegram

Telegram-бот интернет-магазина: каталог с фото, корзина, оформление доставки, оплата картой прямо в Telegram и панель продавца. Для примера взят магазин кофе, но каталог меняется из админки без правки кода.

**Стек:** Python 3.11+, aiogram 3, SQLite, Telegram Payments (ЮKassa или Telegram Stars).

## Что умеет

**Покупатель**
- Каталог: разделы → товары → карточка с фото, ценой и остатком
- Корзина: ➖/➕ прямо в списке, очистка, итог
- Оформление: имя → телефон (кнопкой или текстом) → адрес → подтверждение
- Оплата в Telegram: картой через ЮKassa или звёздами Telegram
- «Мои заказы» со статусами; уведомления, когда заказ отправлен и получен

**Продавец (`/admin`)**
- Уведомление о каждом оплаченном заказе с составом, контактами и адресом
- Заказы по статусам; перевод «Оплачен → Отправлен → Получен» в один клик, покупатель получает сообщение
- Добавление товара по шагам: раздел (можно создать новый), название, описание, цена, остаток, фото
- Список товаров: изменить остаток, скрыть или вернуть в продажу

**Надёжность**
- Нельзя продать больше, чем есть: остаток защищён правилом `CHECK (stock >= 0)` в базе. Если двое одновременно оплатят последний товар, база спишет его только одному, а продавец получит предупреждение о втором заказе (`db.py`, `mark_paid`)
- Остатки проверяются трижды: при добавлении в корзину, при оформлении и перед списанием денег (`pre_checkout_query`)
- Повторное уведомление об оплате от Telegram ничего не ломает: товар не спишется дважды
- Старый счёт после оплаты не примет деньги второй раз
- Цены и названия копируются в заказ: правка товара не меняет оплаченные заказы
- Всё, что вводит человек, экранируется: имя вида `<b>Вася` не сломает сообщения
- `/cancel` и `/start` работают на любом шаге

## Структура

```
bot.py           точка входа, порядок роутеров
config.py        настройки из .env
db.py            база: каталог, корзина, заказы, списание остатков
pricing.py       цены и сумма для счёта (чистые функции)
texts.py         тексты сообщений и статусы заказа
keyboards.py     кнопки и CallbackData
handlers/
  common.py      /start, /cancel, /paysupport
  catalog.py     разделы, товары, «в корзину»
  cart.py        корзина и оформление (FSM)
  payments.py    счёт, проверка перед оплатой, успешная оплата, «Мои заказы»
  admin.py       панель продавца
tests/           тесты логики
deploy/          unit-файл systemd
```

## Запуск у себя

1. Создай бота у [@BotFather](https://t.me/BotFather), скопируй токен.
2. Узнай свой Telegram ID у [@userinfobot](https://t.me/userinfobot).
3. Подключи тестовую оплату: в @BotFather открой своего бота → **Payments** → **ЮKassa** → **Connect ЮKassa Test**. Скопируй платёжный токен (в нём есть слово `TEST`).
4. В папке проекта:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # на Windows: copy .env.example .env
```

5. Впиши в `.env` токен бота, свой ID в `ADMIN_IDS` и платёжный токен в `PAYMENT_TOKEN`.
6. `python bot.py` (на Windows можно двойным кликом по `run_bot.bat`), открой бота и нажми /start. Панель продавца — `/admin`.

Для тестовой оплаты подойдут тестовые карты ЮKassa из её документации (раздел «Тестовые банковские карты»). Деньги по ним не списываются.

Тесты: `python -m unittest -v`

## Оплата: карта или звёзды

- **`PAYMENT_TOKEN` заполнен** — оплата картой через подключённого провайдера. Для настоящих денег нужен боевой токен ЮKassa, а для него — самозанятость или ИП и договор с ЮKassa.
- **`PAYMENT_TOKEN` пустой** — оплата в Telegram Stars. Подключать ничего не нужно, сумма пересчитывается по курсу `STAR_RATE_RUB`. Звёзды настоящие, поэтому для тестов используй ЮKassa Test.

## Деплой на VPS (Ubuntu), чтобы бот работал 24/7

```bash
# на сервере под root
apt update && apt install -y python3-venv git
adduser --disabled-password --gecos "" bot
su - bot
git clone <твой-репозиторий> shop_bot && cd shop_bot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
nano .env          # заполнить как локально
exit

# обратно под root
cp /home/bot/shop_bot/deploy/shop-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now shop-bot
systemctl status shop-bot          # должно быть active (running)
journalctl -u shop-bot -f          # живые логи
```

Обновление: `su - bot -c "cd shop_bot && git pull"` и `systemctl restart shop-bot`.

## Как адаптировать под клиента

- **Товары и разделы**: через `/admin` прямо в Telegram. Стартовый каталог — `DEFAULT_CATALOG` в `db.py` (применяется к новой базе).
- **Название магазина**: `SHOP_NAME` в `.env`.
- **Тексты**: `texts.py` и хендлеры в `handlers/`.
